# 架构设计

## 三层分离

```
API 层 (Gin)          → HTTP 路由、参数校验、中间件（鉴权/限流/审计）
Chain 层              → 业务编排（ChainBase + RunModule 调度原语）
Adapter/Service 层    → 站点适配、下载器控制、媒体匹配、通知、调度
```

## 核心模式（借鉴 MoviePilot）

### Chain / Module / Event

- **`core/module.Run[T]`**：按优先级遍历已注册 Module，返回值按 Skip/Continue/Stop 三种语义聚合。这是整个架构的调度原语。
- **`chain.ChainBase`**：内嵌 ModuleManager + EventBus，各业务 Chain（SiteChain/DownloadChain/...）继承它。
- **`core/event`**：广播事件（并发扇出 + panic 隔离）+ 链式事件（优先级串行中间件）。

### Oper 模式（数据访问）

每张表一个 Oper 类（`SiteOper`/`DownloaderOper`/...），封装 GORM 事务 + 敏感字段加解密。

### 配置即代码（站点定义）

站点定义（YAML）驱动抓取——选择器集中在 `site/defaults.go` 一处维护，站点 YAML 仅需 5 行（id/name/urls）。新增站点零代码。

## 后端包组织（19 包，~7500 行）

```
internal/
├── api/              HTTP 边界层
│   ├── middleware/   auth(jwt+apikey) / cors / ratelimit / requestid / accesslog
│   └── v1/           handlers: auth, site, downloader, dashboard, media,
│                      entertainment, filemanager, notification, backup
├── chain/            业务编排: site, download, media, keepseed, notification,
│                      entertainment, dashboard + ChainBase/RunModule
│                      (SiteChain.credential 按 schema 分发：mteam→apiKey / 其余→cookie)
├── core/             config, log, security(jwt/aes/bcrypt), event, module
├── site/             站点适配框架: types, selector(goquery), nologin, registry,
│   └── schemas/      defaults, inspect + nexusphp(search/userinfo/checkin/hr/keepalive) + mteam(JSON API: search/userinfo)
├── downloader/       统一接口 + qb(client/methods/convert + rid sync) + tr(RPC)
│   └── manager/      多实例管理
├── httpclient/       统一抓取: cookie/retry/UA/Cloudflare/SSRF
├── media/            TMDB + Douban + MusicBrainz + NFO
├── filemanager/      WebDAV + Alist
├── cookiecloud/      AES 解密 + host 匹配
├── keepseed/         辅种评分（名称+大小）
├── entertainment/    游戏框架 + 好学(jgg/magic_scratch/medal) + 财神(cspt_scratch)
├── notification/     bark/telegram/webhook + Manager
├── scheduler/        robfig/cron + Recover
├── automation/       7×24: stats-sync + checkin + cookie-keepalive(刷新+回写+告警) + hr-check(未达标/临期告警) + registration(开放检测)
├── backup/           导出/导入(自身格式 + MoviePilot)
├── auth/             好学 VIP 准入 + 激活码(HMAC) + guard
├── web/              go:embed 内嵌前端 + SPA Handler
├── db/               GORM + SQLite/PG + AutoMigrate
│   ├── models/       11 个模型
│   └── oper/         6 个 Oper
└── app/              依赖装配 + HTTP 生命周期
```

## 文件组织原则（可维护性）

- 每个文件单一职责（如 qb/ 拆为 client.go + methods.go + convert.go）
- 超过 ~400 行主动拆分
- 通用工具集中（helpers.go / defaults.go / convert.go）
- 站点 YAML 极简（5 行），选择器自动填充

## 数据流

```
移动端 WebView 登录 → 取 cookie → POST /sites/:id/cookie → 后端 AES 加密存储
                                                                      ↓
automation cron ───────────────────────────────────────────────────→ 站点抓取
  ├── stats-sync: FetchUserInfo → 写 SiteStat → /dashboard 聚合显示
  ├── checkin: POST attendance.php → 日志 + 通知
  ├── cookie-keepalive: 认证 GET 刷新 session + Set-Cookie 轮换回写 + 失效告警
  ├── hr-check: 抓 getusertorrentlist.php?type=hr → 未达标/临期告警
  └── registration: 探测 signup.php → 关闭→开放转换通知
                                                                      ↓
Web UI / Flutter ← GET /dashboard (真实聚合) / GET /downloaders/:id/torrents
```
