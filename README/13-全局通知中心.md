# 全局通知中心

聚合 13 类业务事件为站内通知（持久化 + WS 实时推送 + 外发 bark/tg/webhook），Web/移动端铃铛通知中心。

## 架构

后端 `internal/notice/`：
- `models.Notice`（`Source` 事件 tag / `Key` 去重键 / `Title`/`Body`/`Level`(info/success/warning/danger) / `Read` / `CreatedAt`），AutoMigrate。
- `oper.NoticeOper`：CRUD + `ExistsSince`(去重查询) + `CountUnread`(铃铛角标) + `Cleanup` + `ClearAll`(一键清空)。
- `notice.Service.Notice(ctx, Input, dedup)`：dedup=true 按 `Source+Key` 当天去重（周期事件）；false 一次性。流程：去重 → 写库 → WS 广播 → 外发渠道。
- **循环依赖解耦**：`Service` 用 `Store` 接口（`oper.NoticeOper` 隐式实现，不 import oper，因 oper→monitor→notice）+ `Broadcaster func([]byte)` 回调（app.go 适配 `ws.Hub.Broadcast`，不 import ws，因 ws→oper→monitor→notice）+ 外发用 `notification.Manager`（不用 chain.NotificationChain，避免 chain↔notice）。notice 包只 import db/models + notification。
- WS `notice` 消息体：`{type:"notice",data:{id,source,title,body,level,created_at}}`。
- 每日 `notice-cleanup` 清 30 天前已读通知。

## 去重与 diff 策略

- **周期事件**（站庆/站免/公告/掉线/考核/下载完成/新邮件）：`dedup=true`，`Source+Key` 当天去重，避免 cron 刷屏。
- **一次性事件**（备份完成/导入、辅种完成）：`dedup=false`。
- **新邮件**：`messages-check` cron（`MESSAGES_CRON`）调 `MessagesAll`，seen message ID 集合存 `SystemConfig`（key `mail:seen:站名` JSON），diff 出新 ID 通知。
- **下载完成**：`ws.Broadcaster` 每 2s 聚合所有种子，内存 `map[dlID:hash]→done` diff（State=completed 或 CompletedAt 非零）；**冷启动首轮只填充 map 不通知**（primed 标记），避免重启把所有已完成种子当新通知。
- **新公告**：RawText 的 sha256 存 `SystemConfig`（key `announce:seen:站名`），变化才通知；首次不通知。
- **考核**：`assessSite` 在 BatchUpsert 前 `FindBySite` 读旧 Status，转换到 COMPLETED/FAILED 才通知；首次该任务无旧记录跳过。

## 配置

| 变量 | 默认 | 说明 |
|---|---|---|
| `MESSAGES_CRON` | `*/30 * * * *` | 站点私信新邮件轮询（通知中心「新邮件」来源）|

## 三端入口

- **Web**：`MainLayout` topbar 铃铛（`NotificationCenter.vue`）+ 未读角标 + 下拉列表（单条已读/删除/全部已读/清空）；WS `notice` 实时追加（`useWs.notices`）+ `noticeApi.list` 初始。
- **Mobile**：`home_shell` FAB 铃铛（`ValueListenableBuilder noticeUnread`）+ `NoticePage`（滑动删除/全部已读/清空）；`WsClient.notices` 流 + `refreshNoticeUnread`。
