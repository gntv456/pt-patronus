# PTPatronus 发布与在线更新指南

> 本项目以 **AGPL-3.0-or-later** 开源（见 [LICENSE](../LICENSE)）。本文面向维护者：
> 如何发版、如何维护官方 update manifest、各客户端形态如何拿到更新。

## 一、日常发版

打 `v*` tag 触发 CI（docker / release / flutter-release）。前置只需一步：

1. **改版本号（单一真源）**：[backend/internal/version/version.go](../backend/internal/version/version.go)。
   前端（设置·关于）与移动端（账户页）**运行时读后端版本**，各自仅留离线兜底常量；
   `mobile/pubspec.yaml` 的 `version:` 是 Android versionCode / iOS build 元数据，
   发布时同步递增 buildCode 即可，显示版本与它解耦。
2. **打 tag**：`git tag vX.Y.Z && git push origin vX.Y.Z`（必须 `v` 前缀）。
3. **等 CI**，产出多架构镜像 `ghcr.io/gntv456/pt-patronus:vX.Y.Z`（Trivy CRITICAL 门禁 + cosign 签名）。
4. **更新官方 manifest**：`update-manifest.json`（改 `latestVersion` / `releaseNotes` /
   `targets.docker.image`，已发布客户端产物的平台回填 `url`+`sha256`），跑
   `node scripts/validate-update-manifest.mjs` 校验后提交。
   - ⚠ **只填了 sha256 没填 url 的平台会被视为「未发布」**：后端 `Check` 对该平台
     直接回 `hasUpdate=false`（弹更新框但下载是死按钮，不如不弹）。
   - 浏览器扩展不需要 target：用户从 Web「设置 → 关于 → 下载浏览器扩展」拿
     `/api/v1/system/extension.zip`（后端 embed，随版本走）。

## 二、在线更新机制

部署的实例拉**官方 manifest** 检查更新，客户端经 `/system/update/check` 中转
（客户端不直连官方源）。manifest 由维护者维护在仓库根 `update-manifest.json`，
其 `UPDATE_MANIFEST_URL` 指向它的 raw 地址（compose 默认已配官方源，自托管清单
才需要改）。

### manifest 形态

```json
{
  "latestVersion": "1.03.29",
  "minVersion": "1.03.20",
  "releaseName": "…",
  "releaseNotes": "…",
  "isForced": false,
  "publishedAt": "2026-11-10T00:00:00Z",
  "targets": {
    "docker": {
      "image": "ghcr.io/gntv456/pt-patronus:1.03.29",
      "instructions": "docker compose pull && docker compose up -d"
    },
    "android": { "url": "https://…/app.apk", "sha256": "<64hex>" }
  }
}
```

### 各形态落地

| 形态 | 发现新版后 |
|---|---|
| docker 服务端 | Web「设置→关于→检查更新」提示 + 一键复制 `docker compose pull && up -d` |
| 手机 / 桌面 | 启动自动检查 + 账户页「检查更新」；平台 target 有 `url`+`sha256` 时弹更新框，缺任一则**不弹**（避免死按钮） |
| 浏览器扩展 | 随服务端版本更新（embed 分发），无需单独通道 |

### 自托管清单（可选）

管理员 `POST /api/v1/admin/update/manifest` 写本地清单（落盘 `data/update-manifest.json`），
优先级高于官方源；`latestVersion` 留空即清除、回退官方源。

## 三、发版前自检清单

- [ ] `go test ./...` / `npm test` / `flutter test` 全绿（CI 会再跑一遍）
- [ ] `bash scripts/check_file_length.sh`（400 行 / 80 列棘轮）
- [ ] 改过 `extension/` 则重跑 `python scripts/pack-extension.py`（embed zip 保鲜）
- [ ] `node scripts/validate-update-manifest.mjs` 通过
- [ ] CHANGELOG.md 有对应版本条目（升级注意写清需要用户做什么）
