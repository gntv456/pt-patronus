# 快速开始（用户指南）

> 本文档面向**使用者**（不是开发者）。从零到仪表盘出数据，按顺序走完 5 步。
> 开发/编译/贡献请看 [07-开发指南](07-开发指南.md)。

## 你将得到什么

PT 守护神是一个自托管的 PT 工具箱：站点数据仪表、H&R 告警、自动签到、
Cookie 保活、跨站搜索/辅种、RSS 订阅、下载器管理、媒体推荐、AI 助手。

## 第 1 步：部署服务端（Docker）

```bash
mkdir ptpatronus && cd ptpatronus
# 下载 docker-compose.example.yml 为 docker-compose.yml
docker compose up -d
```

- 默认端口 `8088`，浏览器打开 `http://<NAS的IP>:8088`
- 首次启动自动生成随机密钥（存 `./data/`），**不要删 data 目录**（删了 = 所有站点 Cookie 丢失 + 全员被踢下线）
- 数据库默认 SQLite，无需配置
- ⚠ **example compose 已预设管理员账号**（`ADMIN_USERNAME: admin` + `ADMIN_PASSWORD: 'ChangeMe_StrongPass123!'`，后者是公开仓库里的公开字符串）。上线前先把 `ADMIN_PASSWORD` 改成你自己的密码再 `up -d`；或者删掉这两行环境变量，走第 2 步方式 A 的首登建号。不改密码直接公网暴露 = 任何人都能用公开的默认密码登进你的实例。

> ⚠ 安全提示：compose 文件里 `docker.sock` 与宿主目录挂载默认是注释掉的。
> 只有你需要「运维中心 Docker 管理」或「文件管理器浏览宿主文件」时才手动打开，
> 并且尽量只挂单个目录（如 `/vol1:/hostfs/vol1`）而不是整个 `/`。

## 第 2 步：登录（本地账号）

登录页输入**用户名 + 密码**即可（单表单，无需选择登录方式）。不需要好学账号、Cookie、2FA 或 VIP 资格。

### 全新部署

**方式 A：登录页首登建号**（仅当 compose **未设** `ADMIN_PASSWORD` 时可用——example 模板已预设，照抄模板请直接用预设的 `admin` 账号登录或先改密码）
1. 打开 `http://<NAS的IP>:8088`
2. 输入任意用户名 + 密码（至少 8 位，含字母和数字）
3. 首次登录自动创建账号并成为管理员
4. 登录后到顶栏用户菜单「修改密码」可随时改密

**方式 B（推荐公网/NAS）：compose 直接预设账号**

在 compose 的 `environment` 里加两行，启动即建好管理员，堵住「谁先打开页面谁拿 admin」的抢注窗口：

```yaml
      ADMIN_USERNAME: admin
      ADMIN_PASSWORD: 'Abcd12345678'      # ≥8 位且含字母和数字
```

明文会被 `docker inspect` 看到，生产建议改成文件方式（优先于明文，文件权限设 600）：

```yaml
      ADMIN_PASSWORD_FILE: /run/secrets/ptp_admin_pw
```

密码不合规或文件读不到会**拒绝启动**，不会静默留一个弱口令实例。引导成功后可以把这两行删掉——账号已落库，删了不影响登录。
**按实例状态自动判断**：空库 → 建管理员；存量账号无本地密码 → 原地补密码（见下）；已有密码 → 忽略，绝不覆盖你在 UI 改过的密码。

> ⚠ 账号引导需 **≥1.03.29** 镜像。`1.03.28` 及更早版本会静默忽略这几个变量，仍走方式 A 的首登建号。

> 单用户实例：已有账号后不允许自助注册第二个账号（返回 403）。

### 从旧版（好学 VIP 账号）升级

**不用迁移数据**：站点、下载器、订阅、通知等配置都是全局表，不按登录账号归属；唯一按 uid 存的是界面偏好。只要登录的还是原来那条账号记录（`User.ID` 不变），所有配置原样可见。

**最省事：什么都不用做**（旧会话还有效时）。升级后打开 Web，系统检测到账号还没有本地密码，会自动弹「升级后首次设置本地密码」，设一次即可——不用敲命令、不用改 compose，原来的配置全在。设完的密码是全账号级的，移动端 / 浏览器扩展之后也用它登录。

> 安全边界：该入口在 guarded 路由上，必须带着有效 JWT（即本来就已登录）才能设密；未登录的人不能凭用户名认领管理员。

如果旧会话已过期（超过 JWT 绝对寿命 7 天），或你平时只用移动端 / 扩展、不方便开 Web，才需要下面的一次性动作 —— compose 的 `environment` 里加一行，重启：

```yaml
      ADMIN_PASSWORD: 'Abcd12345678'      # ≥8 位且含字母和数字
```

```bash
docker compose up -d
```

后端启动时给存量账号**原地补本地密码**，不改 ID / 用户名、不新建平行账号；之后用**原来的用户名** + 这个密码登录。`ADMIN_USERNAME` 在升级路径下会被忽略（不能改老账号身份）。引导成功后可把这行删掉。

不设 env 时走离线 CLI，效果等价：

```bash
docker compose exec ptpatronus reset-admin --password 'Abcd12345678'
```

命令打印 `已为实例主人 "xxx" 设置本地密码`，用该用户名登录。

> 升级前备份 `./data/`，**千万别换卷路径或删 data**：里面除 SQLite 外还有 `secret_key`，密钥变了会让已加密的站点 Cookie / API Key 解不开（表现像「配置丢了」）。账号引导需 ≥1.03.29；更早版本仍只能用 CLI。
> 迁移不要删 `./data/`：里面除数据库外还有自动生成的密钥，删了已加密的站点凭据会失效。

## 第 3 步：添加下载器（qBittorrent 示例）

1. 左侧菜单 → **下载器** → **添加**
2. 填写：
   - 类型：qBittorrent
   - 地址：`http://<下载器IP>:8080`
   - 用户名/密码：qBittorrent 的 WebUI 账号密码
3. 点 **测试连接** → 显示成功后保存

> qBittorrent 需要在 设置 → Web UI 里勾选「对 localhost 之外的请求进行身份验证」，
> 并建议固定 WebUI 端口。

## 第 4 步：添加 PT 站点

1. 左侧菜单 → **站点** → **添加站点**
2. 先搜并**选站点定义**（下拉里按站名搜索，决定抓取方式；没有对应定义的站点暂不支持），再填**名称**与站点地址（如 `https://pt.xxx.org`）
3. 按站点类型填凭据：多数站填 **Cookie**（浏览器登录该站后 F12 → Network → 请求头里复制整串 Cookie；这是**PT 站点**的 Cookie，与 PTPatronus 登录账号无关）；馒头等 API 站填 API Key；猪猪等新型站填用户名+密码——表单会按所选定义提示
4. 保存后点 **同步**，站点数据（上传/下载/做种/魔力值）开始入库
5. 数据每 30 分钟自动刷新一次；也可手动点刷新

### 常见问题：加了站点但数据全是 0？
- 多半是 Cookie 失效：重新按 F12 方式取一次 Cookie 覆盖
- 或站点改版导致选择器失配：到 设置 → 运行日志 看抓取报错，反馈给开发者

## 第 5 步：打开仪表盘

顶部 **仪表盘** 现在应该有数据了：站点上传/下载趋势、H&R 预警、做种列表。

## 浏览器扩展（Cookie 保活 + 辅种）

1. 设置 → 关于 → 下载扩展 zip，Chrome「开发者模式 → 加载已解压的扩展程序」
2. 扩展选项页用本地账号（与 Web 相同的用户名/密码）登录
3. 点「同步站点白名单」——**弹出权限申请时点允许**（读取站点 Cookie 必需）
4. 开启「自动同步」后，浏览器与服务器 Cookie 双向保持新鲜

## 常见问题（FAQ）

**Q：升级后想回退版本？**
先备份 `./data/` 整个目录，再改 compose 里镜像 tag 为旧版本号。
注意：新版可能已升级数据库表结构，回退后若报错，需用备份的 data 恢复。

**Q：忘记密码/管理员丢了？**
服务端机器上执行（会原地重置实例主人的本地密码，账号与数据不变）：
```bash
docker compose exec ptpatronus reset-admin --password '你的新密码'
```
命令行会打印 `已为实例主人 "xxx" 设置本地密码`，用这个用户名 + 新密码登录。

**Q：数据保留多久？**
站点统计与签到记录 90 天、监控快照/告警/通知 30 天（每日 3 点自动清理）。

**Q：遇到问题去哪反馈？**
设置 → 运行日志 导出日志 + 设置 → 诊断中心 跑一次体检，带上版本号反馈。
