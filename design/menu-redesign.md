# PTPatronus 主菜单重构设计稿（定稿 v1）

> 日期：2026-07-13 · 状态：定稿（待进开发） · 范围：Web / Flutter 移动 / Flutter 桌面 三端
> 决策来源：UI 评审拍板 —— AI 仅顶栏、移动端不回归底栏、站点详情用 Tab、云盘合并进文件、消息/公告/娱乐/勋章/后宫/下载器/媒体服务器/插件不移出菜单

> **修订（2026-07-22）**：搜索由「侧栏 + 顶栏双入口」收敛为**仅顶栏常驻**（顶栏放大镜图标直达 `/search`，位于折叠导航按钮右侧）。理由：搜索是横向跳转能力而非具体任务域，放顶栏更贴合「主菜单只回答我今天做什么」。注：⌘K 命令面板仍为后续 P0 蓝图（见 §10），当前顶栏先以图标形态落地。

> **修订（2026-07-23，v2）**：复审发现三处需修订——① **§10 执行顺序缺陷**：原 P0「移除 16 项菜单」的替代触达（站点详情 Tab / 设置分区 / 仪表盘卡片）全排在 P1，移除即制造功能孤儿。本次将「移除菜单项」后移至 P2，待替代触达就绪再删。② **§5.2 云盘方案需分层**：现状 FileManager 已统一本地+云盘浏览 + STRM 动作，但 Cloud 的账号/规则/追更是配置类，应进设置而非塞文件页。③ **§5.3 设置 6 分区过时**：项目后续已长出 9 个设置 Tab（OIDC / AI 网关 / CookieCloud / Servarr / TG Bot / 调度 …），原蓝图未覆盖，按现状重画。另补 §6.2 移动端搜索/日志同步条款。**已落地**：AI 顶栏 ✅、搜索顶栏 ✅（均 Web 端）。

## 0. 一句话定调

**主菜单只回答"我今天要做什么"，具体功能在它最该出现的上下文里出现。**
从现状（Web 30 项 / 移动 34 项，均 4 组平铺）→ **17 项 / 6 组**，其余项全部配替代触达路径 + ⌘K 兜底，不丢任何功能。
> 基线说明：原稿「35 项」为重构启动前快照；AI、搜索已移顶栏，期间又新增若干页，基线随开发变动，以两端 `navGroups` 实际为准。

## 1. 问题诊断（重构前）

| 维度 | 现状 | 问题 |
|---|---|---|
| 入口总数 | Web 32 + 移动底部 3 = **35** | 远超米勒定律，靠"记位置"而非"扫描" |
| 单组规模 | 基础设施 12、内容获取 8、站点活动 8 | 分组形同虚设，组内仍长列表 |
| 层级 | 全一级，无折叠/子菜单 | Web `.nav` 已 `overflow-y:auto` 标准视口即溢出 |
| 快速访问层 | ❌ 无命令面板/收藏/最近 | 新手唯一路径＝扫读 35 项 |
| 顶栏 | 只有 `☰+通知+用户`，中间空白 | 黄金跳转位闲置 |
| 移动端 | 35 项全进抽屉 | 一屏 5–6 项，滚 6 屏到底 |

---

## 2. 设计原则

1. **任务驱动**——按"用户要完成的事"组织，不按"系统有什么模块"。
2. **上下文触达优先**——per-site 功能进站点详情；配置类进设置。
3. **做减法但不丢失**——移出菜单的每项必有可发现替代路径；⌘K 全量兜底。
4. **三层访问梯度**——高频常驻 → 中频上下文 → 低频可搜。
5. **渐进披露**——组可折叠，详情可下钻。

## 5. 替代触达路径设计

移出菜单的 16 项靠这四条路径消化（通知中心不再吞消息/公告，更多页取消）。

### 5.1 站点详情聚合页（消化 B 类 6 项，Tab 形态）

点任意站点 → 顶部 Tab 承载所有 per-site 活动：

```
┌──────────────────────────────────────────────────────┐
│ ◀ 站点 [好大]  ●在线  等级 User  上传 1.2T           │
├──────────────────────────────────────────────────────┤
│ 概览 │ 考核·契约 │ 刷流 │ 辅种 │ 站免 │ 监护         │   ← 后宫不在此（留菜单）
├──────────────────────────────────────────────────────┤
│  考核·契约                                            │
│  ┌─────────┐ ┌─────────┐ ┌─────────┐                │
│  │ 保级进度 │ │ 分享率   │ │ 上传差额 │                │
│  │  78%     │ │  2.31    │ │  +120G   │                │
│  └─────────┘ └─────────┘ └─────────┘                │
│  告警阈值（契约）：[编辑]                             │
└──────────────────────────────────────────────────────┘
```

吸收：考核、保种契约、刷流、辅种、站免、监护室 → **6 项出菜单**。

> **v2 双层（三项目对照后修订）**：这 6 项的首要场景是**跨站全局总览**（"所有站的考核进度""全站免费""所有辅种任务"），旧版 PTPatronus 正是把它们做成独立全局页。因此站点详情 Tab 是**下钻入口**而非唯一入口——全局总览由 §5.4 仪表盘任务卡片（D 类）+ ⌘K 命令面板承载，点卡片/结果再下钻到某站的对应 Tab。辅种尤其特殊：PT-depiler 用「任务维度」（一个基准种子 + 多站替代种子，跨站），我们 Reseed 现按下载器维度——辅种 Tab 内宜支持任务视角（跨站保活），不限于单站。

### 5.2 文件页升级为统一存储浏览器（消化 云盘）

文件页左侧/顶部切换存储后端，STRM 作为选中动作：

```
┌──────────────────────────────────────────────────────┐
│ 文件   [本地] [NAS] [115] [夸克] [123]   🔗连通性 ▾   │
├──────────────────────────────────────────────────────┤
│  路径 /Movies/2025                                   │
│  ☐ movieA.mkv   4.2G   [生成 STRM] [整理]            │
│  ☐ movieB.mkv   3.8G   [生成 STRM] [整理]            │
│  …                                                   │
│  已选 2  → [批量生成 STRM] [批量整理]                 │
└──────────────────────────────────────────────────────┘
```

复用既有 `StorageBackend` 抽象。**v2 分层（替代原「云盘整体并入文件」）**：

- **浏览 + STRM 生成** → 文件页（**已完成**：`FileManager.vue` 已统一 `StorageItem = {fs | cloud}`，左栏混合本地+云盘，STRM 作为动作列，云盘以只读混入）；
- **云盘账号 CRUD / STRM 规则 / STRM 记录 / 订阅追更** → 设置「连接」分区（配置类，不该塞浏览器页）。

> 现状：`Cloud.vue` 仍独立保留账号/规则/记录/追更全套管理。P1 拆分时浏览能力留 `FileManager`，管理能力迁入设置「连接」，`Cloud.vue` 作深链跳板保留 30 天后下线；云盘"订阅追更"并到订阅页。**云盘 1 项出菜单**（进设置）。

### 5.3 系统设置收纳器（消化 C 类，v2 按现状重画）

现状 `Settings.vue` 已是 `el-tabs` 多 Tab 结构（**9 Tab**：通用 / 通知 / OIDC / AI 网关 / CookieCloud / 调度频率 / TG Bot / Servarr / 运行日志），另有 **5 个独立配置页**待并入（Trakt / MediaQuality / Subtitle / Backup / Doctor），外加 FilterRules / MediaSettings。按现状重画为 6 分区映射：

| 分区 | 现状项（迁入来源） |
|---|---|
| **连接** | Trakt ✦ · 云盘账号 ✦(§5.2) · OIDC/SSO · AI 网关 · Servarr 兼容 · CookieCloud |
| **媒体** | 媒体质量 ✦ · 字幕源 ✦ · MediaSettings · 过滤规则 ✦ · 整理规则 |
| **自动化** | 调度频率（聚合快照 cron）· 刷流默认策略 · 目录监视 |
| **通知** | 通知通道 · TG Bot · 告警规则 |
| **维护** | 备份 ✦ · 诊断 ✦ · 运行日志（已在设置）· 安全模式 |
| **通用** | 主题 · 语言 · 版本/更新检查 |

> ✦ = 当前为独立路由页，需迁入对应分区；其余项已在 `Settings.vue`，仅做分区归类。
> 注：刷流默认策略 / 整理规则 / 目录监视 / 告警规则 / 安全模式 为目标位，存在性以代码为准。

吸收后出菜单：Trakt / 媒体质量 / 字幕 / 过滤规则 / 备份 / 诊断 / 运行日志 /（云盘账号 见 §5.2）→ 配置类全部进设置。RSS 进订阅页 Tab 另计。

### 5.4 仪表盘任务卡片 + 命令面板 ⌘K

- **仪表盘卡片**：保级风险 / 待整理 / 刷流中 / 站点健康 / 辅种建议 / 健康自检，点卡片直达对应功能。被动消费 → 主动推送入口。
- **⌘K 命令面板**：全部 35 项 + AI 指令 + 最近访问，fuzzy 匹配（含 PT 黑话：刷流/保级/H&R），老用户零学习成本。

## 7. 命令面板 ⌘K 交互

- **唤起**：`Ctrl/⌘+K`（Web）、顶栏搜索框点击（三端）。
- **匹配**：fuzzy 命中 35 项 label + 别名（刷流/保级/H&R）+ 描述。
- **分组**：最近访问 / 跳转 / 动作 / AI 提问。空输入显「最近 5 + 收藏」。
- **键位**：↑↓ 选、⏎ 跳、`⌘+⏎` 新标签、Esc 关。
- **动作项**：一键整理 / 全站刷流 / 切主题 等直达。
- **AI 模式**：`?` 或 `问 ` 开头转 AI 助手。

> **与搜索同源（参考 MP `SearchBarDialog`）**：顶栏搜索入口即命令面板——桌面顶栏常驻输入框、聚焦展开浮层；移动端图标触发全屏浮层；`⌘K` 等价点搜索。命中菜单/插件/设置 Tab → 跳转；命中媒体/种子 → 带 query 跳 `/search` 工作台。当前实现的「图标直跳 /search 页」为过渡态，P0 落地命令面板时升级为浮层入口，消除「搜索页 vs 命令面板」割裂（MP 验证：搜索与命令面板是同一个组件，非两个）。

## 11. 剩余开放点

- **云盘合并进文件**：v2 已由 §5.2 分层方案解决（浏览+STRM 留文件页 / 账号+规则+追更 进设置「连接」），不再纠结整体合并。
- **插件侧栏注入（参考 MP `pluginSidebarNavStore`）**：现状插件为独立菜单页。可扩展为插件向后端声明侧栏入口（`plugin_id`/`nav_key`/`title`/`icon`/`section`），前端拉取后按 section 注入对应分组、与原生菜单混排，增强插件 UI 可发现性。代价是菜单变动态、需权限过滤。列后续增强，不阻塞 P0–P3。
- **运维工具弹窗化（参考 MP `ShortcutBar`）**：诊断 / 网络测试 / 缓存 等一次性运维工具，可做顶栏工具箱弹窗（2×N 网格、`openSharedDialog`）随时唤起，而非全进设置。v2 现归设置「维护」更收敛；若实测运维高频可回退此案。
- **MP 不构成参照的两块**：per-site 功能（辅种/刷流/考核/契约/监护——MP 无此概念，§5.1 站点详情 6-Tab 是我们的创新，保持）、移动端（MP 为 PWA 无 Flutter，我们的 Flutter 独立端 P3 同步保持）。
- **辅种任务维度视图（PT-depiler 启发）**：PT-depiler 辅种按「任务」（基准种子 + 多站替代种子）组织，跨站；我们现按下载器维度。与 §5.1 双层一致，辅种是否补一个跨站任务总览视图待定。
- **站点详情渐进式缓存（旧版启发）**：旧版 UserProfile 用「DB 缓存秒开 + 1h stale」策略（避免每次进入发 2–6 个 HTTP）；新版站点详情 Tab 化时复刻此策略。实现细节，P1 落地。
- **搜索方案抽象（PT-depiler 启发）**：PT-depiler `SetSearchSolution` 允许自定义「哪些站怎么搜 / 合并去重」；未来搜索策略模板可参考，非本轮范围。
